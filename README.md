# Тестовое задание для фронтенд-разработчика

Нужно сделать интерфейс магазина: каталог, корзину, оформление заказа и оплату тестовой картой. Бэкенд готов, фронтенд — в `apps/web`.

[Условия задания](docs/ASSIGNMENT.md) · [Работа с API](docs/INTEGRATION.md) · [Критерии оценки](docs/EVALUATION.md)

## Запуск

Потребуются Node.js 24.x и npm 11.x. Отдельная база данных и ключи внешних сервисов не нужны.

```sh
git clone https://github.com/i-Living/frontend-checkout-challenge.git
cd frontend-checkout-challenge
npm ci
```

Терминал 1 — API (`127.0.0.1:4000`):

```sh
npm run dev
```

Swagger: [http://localhost:4000/docs/](http://localhost:4000/docs/). Спецификация: [http://localhost:4000/openapi.json](http://localhost:4000/openapi.json) или [файл в репозитории](docs/openapi.json).

В Swagger выполните `POST /api/sessions` с телом `{}`. Скопируйте `data.token` в **Authorize**, без слова `Bearer`.

Терминал 2 — фронтенд (Vite, порт 5173):

```sh
npm run dev -w @checkout/web
```

Откройте [http://localhost:5173/](http://localhost:5173/). Базовый URL API задаётся через `VITE_API_URL` (по умолчанию `http://127.0.0.1:4000`, см. `apps/web/.env.example`).

## Сборка и проверки

```sh
npm run build -w @checkout/web
npm run typecheck -w @checkout/web
npm test -w @checkout/web
npm run build          # contracts + api
npm start              # собранный бэкенд
npm run check          # Biome, тесты API, typecheck/тесты/сборка web, OpenAPI
```

При работающем API в другом терминале: `npm run smoke` — покупка, отказ карты, отмена и повтор оплаты по HTTP.

## Решение

React + Vite + TypeScript. Серверное состояние — TanStack Query, клиентское — Zustand. Стили — Tailwind CSS v4, компоненты — shadcn/ui.

### Состояние

- **TanStack Query** — каталог, корзина, опции оформления, расчёт доставки, заказ, платежи, тестовые карты, опрос оплаты.
- **Zustand** (`persist` в `sessionStorage`, ключ `checkout.v1`) — токен сессии, текущие `orderId` / `paymentId`, черновик формы, последние тело и `Idempotency-Key` заказа и оплаты.

После перезагрузки вкладки восстанавливаются сессия, корзина (по токену) и текущий заказ. Если оплата ещё обрабатывается, опрос статуса продолжается.

### HTTP-клиент (критерий D2)

Один модуль соединения — `apps/web/src/shared/api/client.ts`: базовый URL, заголовок `Authorization: Bearer <token>`, `Idempotency-Key`, разбор JSON и `204`, маппинг в `ApiError`. Страницы `fetch` не вызывают.

| Файл | Что менять отдельно |
| --- | --- |
| `shared/api/client.ts` | базовый URL, заголовки, отправка, разбор ответа |
| `shared/api/errors.ts` | тип `ApiError`, `toUserMessage` / `toErrorTitle` / `getErrorCode` |
| `shared/api/endpoints.ts` | обёртки эндпоинтов, повтор 401 в одном `withSessionRetry` |
| `shared/api/queries.ts` | хуки `useCart` / `useProducts` / `useOrder` / … |
| `shared/api/invalidate.ts` | сброс кэша по сущностям |
| `shared/api/idempotency.ts`, `query-keys.ts`, `session.ts` | ключи повтора, ключи кэша, гостевая сессия |

Мутации корзины — `features/cart/use-cart-mutations.ts` (одно правило для каталога и корзины). Новый запрос: эндпоинт + ключ + хук, без копирования настройки соединения и без правок страниц.

Типы ответов генерируются из OpenAPI (`npm run generate:api-types` → `generated.d.ts`), руками не описываются.

### Маршруты

| Путь | Экран |
| --- | --- |
| `/` | каталог |
| `/cart` | корзина |
| `/checkout` | контакты, доставка, расчёт, создание заказа |
| `/orders/:orderId/pay` | тестовая карта и ожидание оплаты |
| `/orders/:orderId` | статус и страница успеха |

Страница успеха читает заказ с сервера. Для карты нужны `status=paid` и `paymentStatus=succeeded`. Для наличных заказ сразу `confirmed` / `unpaid`, онлайн-оплата не вызывается.

### Проверенные сценарии

- Каталог из API, доступный товар в серверную корзину; `stock = 0` недоступен.
- Количество меняется абсолютным `PUT`, позиция удаляется, итог совпадает с `GET /api/cart`.
- Контакты, самовывоз с пунктом и курьер с адресом; подписи и пункты — из `GET /api/checkout/options`.
- Смена товаров или доставки даёт новый расчёт; доставка и итог — из quote, не считаются на клиенте.
- Заказ с выбранной оплатой. В форме карты — название и маска из `GET /api/sandbox`, без PAN/CVC.
- После «Оплатить» видно ожидание. Успех только по итоговому статусу заказа.
- Страница успеха: номер, товары, доставка и сумма этого заказа.
- Наличные: «Заказ оформлен, оплата при получении», без попытки онлайн-оплаты.
- Отказ карты (`failed` / `CARD_DECLINED`, HTTP 200) и отмена до оплаты (`cancelled`) различимы; после каждого можно оплатить тот же заказ новой попыткой.
- Двойное нажатие и повтор сети не создают второй заказ или платёж: те же тело и `Idempotency-Key`. Новая попытка — новый ключ.
- Перезагрузка восстанавливает сессию, корзину и заказ; незавершённая оплата доводится до результата.
- `CART_VERSION_CONFLICT` / `QUOTE_EXPIRED`: данные обновляются, форму можно продолжить.
- Сбой сети не стирает форму; запоздавший ответ не затирает более новый расчёт или статус оплаты.
- Пустую корзину нельзя оформить; превышение остатка обработано; опрос оплаты останавливается на терминальном статусе и при уходе со страницы.
- Сценарий проходит при ширине 1280 и 390 px, поля с подписями, форма с клавиатуры.

Автопроверки: `npm run smoke`, `npm test -w @checkout/web`.

### Недоработки

Отменить уже ушедшую в банк попытку нельзя: у платежа одна симуляция. «Отменить оплату» закрывает форму до нажатия «Оплатить»; во время обработки кнопка неактивна.

### Время

Около 8 часов.

## Структура

```text
apps/api/             бэкенд (не менялся)
apps/web/             фронтенд `@checkout/web`
packages/contracts/   схемы API и типы TypeScript
docs/                 задание и документация
scripts/              проверки
```

Проект использует npm workspaces. Корневой `npm run dev` запускает только API; фронтенд — отдельной командой выше.

## Настройки

Адрес API по умолчанию — `127.0.0.1:4000`. Если порт занят, скопируйте `.env.example` в `.env` и измените `PORT`. Для проверки другого порта: `BASE_URL=http://localhost:4100 npm run smoke`.

Фронтенд может работать на любом HTTP-порту `localhost`, `127.0.0.1` или `[::1]`. Другие разрешённые адреса задаются в `CORS_ORIGINS`. Авторизация передаётся заголовком; cookies и `credentials: include` не нужны.

Данные сохраняются в `.data/store.json`. Запускайте один экземпляр API на один файл. Для сброса остановите сервер и выполните `npm run data:reset`; затем создайте новую сессию.

Товары и адреса вымышленные. Остаток ограничивает количество в одной корзине и не уменьшается у других покупателей. Для получателя подойдут тестовые контакты, например `buyer@example.test`.
