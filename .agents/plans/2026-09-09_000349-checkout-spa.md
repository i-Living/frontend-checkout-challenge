# Checkout SPA — план реализации

> Реализовывать только после подтверждения. Коммиты — только по явной просьбе. Не переключать ветки.

**Goal:** SPA в `apps/web` (`@checkout/web`): каталог → корзина → оформление → тестовая оплата / наличные, по `docs/ASSIGNMENT.md` + `docs/INTEGRATION.md`, на 100 баллов `docs/EVALUATION.md`.

**Architecture:** Vite SPA без SSR. Один HTTP-клиент (D2): base URL, `Authorization`, JSON/`204`, разбор ошибок. Серверное состояние — TanStack Query; черновик формы и id сессии/заказа — Zustand + `sessionStorage`. Успех только после `GET /api/orders/{id}`.

**Tech Stack (зафиксировано AGENTS.md, не менять):** npm workspaces, Node 24, React + Vite, Zustand + TanStack Query, Tailwind CSS v4 (`@tailwindcss/vite`, без PostCSS), shadcn/ui + lucide-react, openapi-typescript (`src/shared/api/generated.d.ts`), Biome. Не bun/yarn/pnpm. Не трогать `apps/api` и `packages/contracts`.

---

## Контекст

`apps/web` сейчас заглушка: `generate:api-types`, `typecheck`, уже есть `generated.d.ts`. Vite-приложения нет. `npm run dev` в корне поднимает только API `127.0.0.1:4000`. Корневые скрипты не менять без спроса — `dev`/`build` фронта живут в `@checkout/web`, в README решения.

Ориентир задания: 6–8 часов. Сначала полный основной путь (A1–A8), потом устойчивость (B), потом полировка C/D/E. Порог отбора: ≥75, из них ≥30 за A и ≥15 за B; вымышленный успех или молчаливая потеря данных — дисквалификация пути.

## Допущения

1. Vite, не Next — сессия это клиентский Bearer-токен.
2. UI на русском, как тексты API и каталога.
3. Деньги только из API, копейки → `Intl.NumberFormat('ru-RU', { style: 'currency', currency: 'RUB' })` от `amount / 100`.
4. Отмена оплаты — кнопка «Отмена», `scenario: 'cancel'`. В sandbox только две карты (`success` / `decline`), карты cancel нет.
5. Корневой `npm run dev` не трогаем: два терминала (API + Vite).
6. Тесты фронта не обязательны (E1: ручные сценарии в README). Playwright в `.gitignore` не подключаем.
7. ETag / If-Match не делаем.
8. Функциональный TS, без классов. Ошибка API — объект + `isApiError()`, не `class`.

Если какое-то допущение неверно — остановить до кода.

## Потоки API (канон = `scripts/smoke.mjs` + INTEGRATION)

### Карта

1. `POST /api/sessions` `{}` → сохранить `data.token` (не `data.id`)
2. `GET /api/products`
3. `PUT /api/cart/items/{productId}` `{ quantity }` — **абсолютное** число; 201 новая позиция, 200 та же
4. `GET /api/cart` (после каждого изменения)
5. `GET /api/checkout/options`
6. `POST /api/quotes` `{ cartVersion, delivery }`
   - pickup: `{ method: 'pickup', pickupPointId: 'point-center' \| 'point-north' }`
   - courier: `{ method: 'courier', address: { city, street, house, apartment? } }`
7. `POST /api/orders` + `Idempotency-Key` `{ quoteId, paymentMethod: 'card', customer }` → `awaiting_payment` / `unpaid`. Корзина очищается.
8. `POST /api/orders/{orderId}/payments` `{}` + **новый** `Idempotency-Key`
9. `GET /api/sandbox` → выбрать карту по `title` + `maskedNumber`, взять её `scenario`
10. `POST /api/payments/{paymentId}/simulations` `{ scenario }` → обычно 202 + `Retry-After` (`PAYMENT_DELAY_MS=1200`)
11. Poll `GET /api/payments/{id}` пока не `succeeded|failed|cancelled`
12. `GET /api/orders/{id}`: успех только при `status=paid` и `paymentStatus=succeeded`. **201 создания не считать оплатой.**

### Наличные

Шаги 1–6 те же, затем `POST /api/orders` с `paymentMethod: 'cash_on_delivery'` → сразу `confirmed` / `unpaid`. Шаги 8–11 **не вызывать** (`409 PAYMENT_NOT_REQUIRED`).

### Деньги с сервера (не считать на клиенте)

- Самовывоз: shipping 0
- Курьер: 39000 копеек; при `subtotal >= 500000` — 0
- Каталог: лампа 249000, кружка 89000, сумка 159000, часы 329000 / `stock: 0` (`clock-dot`)

## Карта ошибок → UI

Разбирать `error.code`, не текст `message`. `fields[].message` технические — свои подписи у полей.

| HTTP | code | UI |
|---|---|---|
| 401 | `SESSION_REQUIRED` / `SESSION_INVALID` | Новая сессия, повторить запрос |
| 404 | `PRODUCT_NOT_FOUND` | Товар пропал, обновить каталог |
| 404 | `CART_ITEM_NOT_FOUND` | Обновить корзину |
| 409 | `INSUFFICIENT_STOCK` | «Доступно не более N шт.», обновить stock |
| 409 | `CART_VERSION_CONFLICT` | `GET /api/cart`, новый quote, продолжить |
| 409 | `QUOTE_EXPIRED` | Новый quote с тем же delivery, форма жива |
| 422 | `CART_EMPTY` | На корзину, CTA оформления disabled |
| 409 | `IDEMPOTENCY_CONFLICT` | Новый ключ только если body реально другой; иначе баг клиента |
| 409 | `PAYMENT_IN_PROGRESS` | Показать текущую попытку, продолжить poll |
| 409 | `PAYMENT_FINALIZED` | Не менять scenario; после fail/cancel — новая попытка |
| 409 | `ORDER_ALREADY_PAID` | На страницу успеха, `GET` заказа |
| 409 | `PAYMENT_NOT_REQUIRED` | Не вызывать pay для cash |
| 400 | `VALIDATION_ERROR` | Поля по `fields[].path` (`body/customer/email` → email) |
| 200 | payment `failed` + `CARD_DECLINED` | Не HTTP-ошибка. «Карта отклонена», кнопка «Оплатить снова» |
| — | сеть / abort | Форма жива, «Повторить». `AbortError` не показывать как сеть |

`DELETE` → 204: **не** вызывать `response.json()`. Повторное удаление тоже 204.

## HTTP-слой (D2) — страницы не знают `fetch`

```
apps/web/src/shared/api/
  generated.d.ts          # не редактировать
  api-types.ts            # re-export
  client.ts               # base URL, headers, JSON/204, signal
  errors.ts               # ApiError-объект + isApiError
  session.ts              # token get/set, ensureSession
  idempotency.ts          # uuid ключ; last key+body на действие
  query-keys.ts           # плоские примитивы
  endpoints.ts            # одна функция на ресурс
```

Правила клиента:

- `VITE_API_URL` default `http://127.0.0.1:4000`
- `Authorization: Bearer ${token}` только если токен есть; `credentials` не ставить
- `Content-Type: application/json` только если есть body
- `204` / пустое тело → `undefined`
- `signal` из Query прокидывать в `fetch` (отмена на unmount = стоп poll)
- Успех: вернуть `data` (типы из `operations[...]['responses']`)
- Ошибка: `{ name: 'ApiError', message, code, status, fields, requestId }`
- Не ходить по `links` динамически — пути константами, как в OpenAPI

Query keys (плоские, иерархия для invalidate):

```
['session']
['products']
['cart']
['checkout-options']
['quote', quoteId]
['sandbox']
['order', orderId]
['payments', orderId]
['payment', paymentId]
```

Invalidate `['cart']` после PUT/DELETE. После `POST /orders` — invalidate cart + положить order в кэш.

### Идемпотентность (B2)

- Ключ: `crypto.randomUUID()` (8–128, `[-_a-zA-Z0-9]`)
- На время in-flight сохранить `{ key, body }` в store
- Повтор сети / двойной клик: те же key+body
- Успех или смена body: новый ключ
- Разные ключи: `orders` vs `payments:{orderId}`
- Новая попытка оплаты после fail/cancel — **новый** ключ

### Polling (A6, B3, B6)

- `useQuery` payment с `refetchInterval`: если статус `pending|processing` → `max(Retry-After, 400)` мс, иначе `false`
- Стоп: терминальный статус **или** unmount (уход со страницы)
- Generation: игнорировать ответ, если `generation` запроса < текущего
- После терминального статуса — `GET` заказа; UI успеха только от заказа
- Reload на `/orders/:id/pay`: token из storage → `GET order` → если `paymentStatus=pending` — `GET .../payments`, взять последнюю, продолжить poll
- Потеряли `paymentId` → `GET /api/orders/{orderId}/payments` (новые сверху)
- Потеряли `orderId` → `GET /api/orders`, взять актуальный; не выдумывать id
- `POST .../simulations`: 202 (poll + `Retry-After`), 201 (нулевая задержка), 200 (повтор того же scenario). Обработать все три; другой scenario → `409 PAYMENT_FINALIZED`

Persist (`sessionStorage`, ключ `checkout.v1`): `token`, `orderId`, `paymentId`, черновик формы, last idempotency. Корзина на сервере — Query её перечитает.

## Экраны и маршруты

```
/                      каталог
/cart                  корзина
/checkout              контакты + доставка + оплата + quote
/orders/:orderId/pay   тестовая платёжная форма (только card)
/orders/:orderId       итог заказа (успех / ожидание / ошибка)
```

Header: название магазина, ссылка «Корзина (N)» из `cart.quantity`.

### Каталог `/`

Карточка: title, description, цена из `price`, остаток.  
`stock === 0` (`clock-dot`): кнопка disabled «Нет в наличии».  
Иначе «В корзину» → `PUT quantity: currentInCart + 1` (абсолют = уже в корзине + 1, не инкремент API).  
Состояния: skeleton / ошибка+повторить / готово.

### Корзина `/`

Строки: title, qty, `lineTotal`. Итог = `cart.subtotal` (не сумма на клиенте).  
Qty: input/stepper → `PUT` абсолют. Удалить → `DELETE`.  
Пусто: «Корзина пуста», «Оформить заказ» disabled + нет перехода на `/checkout`.  
CTA: «Перейти к оформлению».

### Оформление `/checkout`

Поля (C2): Имя, Email, Телефон, способ доставки, пункт **или** адрес (город, улица, дом, квартира?), способ оплаты.

Пункты выдачи и подписи способов — **только** из `GET /api/checkout/options` (`deliveryMethods[].pickupPoints`, `paymentMethods[].title`). Не хардкодить `point-center` в UI.

Клиентская проверка до POST:

- name: непустая строка
- email: встроенный email
- phone: `/^\+[1-9]\d{9,14}$/`
- pickup: выбран `pickupPointId`
- courier: city, street, house

Quote: при смене delivery или `cart.version` — новый `POST /quotes`. Показать `shipping` и `total` из ответа (placeholder «Считаем доставку…»).

CTA:

- card: «Оформить и перейти к оплате» → order → `/orders/:id/pay`
- cash: «Оформить заказ» → order → `/orders/:id` без pay

Кнопки `disabled` на `isPending`. Пустая корзина → редирект `/cart`.

### Оплата `/orders/:id/pay`

Список карт: `title` + `maskedNumber`. Нет input для номера/CVC.  
Кнопки: «Оплатить» (scenario карты), «Отменить оплату» (`cancel`).  
Ожидание: отдельный блок «Обрабатываем оплату…», кнопки disabled.  
Decline: «Банк отклонил карту», «Оплатить снова».  
Cancel: «Оплата отменена», «Оплатить снова».  
Retry = новый `POST .../payments` + новый ключ, тот же order.

### Успех `/orders/:id`

Сначала `GET` заказа.

- card + `paid`: номер, товары, доставка, сумма
- cash + `confirmed` + `unpaid`: **«Заказ оформлен, оплата при получении»** + те же детали
- `awaiting_payment` + processing: не успех — «Оплата ещё обрабатывается»
- `awaiting_payment` + failed/cancelled/unpaid: ссылка «Вернуться к оплате»

### Копии кнопок (C1)

- В корзину / Нет в наличии
- Удалить
- Перейти к оформлению
- Оформить и перейти к оплате
- Оформить заказ (наличные)
- Оплатить
- Отменить оплату
- Оплатить снова
- Повторить
- Вернуться в каталог

### 1280 / 390 (C3)

- 1280: каталог 2–3 колонки; checkout две колонки (форма \| итог quote sticky)
- 390: одна колонка; CTA на всю ширину, не перекрыта; `overflow-x: hidden` на `body`; поля не уже 44px по высоте
- Не tooltip вместо label (shadcn-mobile)
- `flex-wrap` + `min-w-0` в строках корзины, чтобы цена не вылезала

### Деньги

```ts
export function formatMoney(kopecks: number, currency: 'RUB' = 'RUB') {
    return new Intl.NumberFormat('ru-RU', { style: 'currency', currency }).format(kopecks / 100)
}
```

249000 → «2 490,00 ₽» (или без копеек — главное, не «249000»).  
Склонения: `pluralize(n, 'товар', 'товара', 'товаров')`. Иконки lucide, не emoji.

## Scaffold (точные команды)

Из корня репо, Node 24:

```sh
# зависимости web (версии зафиксирует lockfile)
npm install -w @checkout/web react react-dom react-router \
  @tanstack/react-query zustand lucide-react clsx tailwind-merge

npm install -w @checkout/web -D vite @vitejs/plugin-react \
  tailwindcss @tailwindcss/vite typescript @types/react @types/react-dom

# shadcn в apps/web
cd apps/web && npm exec -- shadcn@latest init
npm exec -- shadcn@latest add button input label radio-group select card skeleton alert
cd ../..
```

`vite.config.ts`: `tailwindcss()` из `@tailwindcss/vite`, **не** postcss.config.  
`src/app/styles.css`: `@import 'tailwindcss';`  
Biome: 4 пробела, single quotes, без `;` — после генерации shadcn прогнать `npm run format`.

QueryClient:

```ts
new QueryClient({
    defaultOptions: {
        queries: { retry: 1, refetchOnWindowFocus: false, staleTime: 5_000 },
        mutations: { retry: 0 },
    },
})
```

Сеть для B5 ретраим явно кнопкой, не бесконечным auto-retry мутаций.

## Риски

| Риск | Почему | Что делаем |
|---|---|---|
| Успех по 201 payment | Снимает приглашение | Success page только `GET order` |
| `PUT` как инкремент | Двойной клик → qty 1, не 2; или наоборот взрыв qty | Всегда слать абсолют из серверной корзины |
| `response.json()` на 204 | Падение на удалении | В клиенте ветка без тела |
| Decline как HTTP error | Ложный баннер ошибки | Ветвление по `data.status` |
| Cancel как третья карта | В API нет | Отдельная кнопка `scenario: 'cancel'` |
| Poll после unmount | B6 | `signal` + `refetchInterval: false` при unmount |
| Stale overwrite | B5 | generation / отмена Query |
| Суммы на клиенте | A4/A7 2 балла | Рендер `quote.total` / `order.total` |
| `npx biome` | Неверный пакет | `npm run format` / `./node_modules/.bin/biome` |
| Корневой `dev` сломан | Рецензент не поднимет API | Не менять root scripts |
| shadcn с `;` и 2 spaces | Хуки pre-commit | Сразу `biome check --write` |
